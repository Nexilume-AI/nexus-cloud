# Accounts Module Constraints

## Scope

This module implements only the account and authentication surface required by the current Nexus CLI commands:

- `nexus login`
- `nexus logout`
- `nexus whoami`
- `nexus account info`
- `nexus account update`
- `nexus account password reset`

No tenant management, role management, invitation flow, email delivery, refresh-token rotation, or password-change confirmation flow is implemented in this module.

## API Contract

All routes live under `/api/v1/` and return the unified response envelope:

```json
{
  "ok": true,
  "data": {},
  "error": null,
  "request_id": "req_xxx"
}
```

Errors use the same envelope with `ok=false`, `data=null`, and `error.code/error.message`.

The implemented routes are:

- `POST /api/v1/auth/login/`
- `POST /api/v1/auth/logout/`
- `GET /api/v1/auth/whoami/`
- `GET /api/v1/account/me/`
- `PATCH /api/v1/account/me/`
- `POST /api/v1/account/password-reset/`

## Authentication

The server accepts `Authorization: Bearer <token>`.

Login returns an HS256 JWT access token and refresh token generated by the server. The access token contains user id, email, tenant id, project id, issuer, audience, issued-at, expiry, token type, and token id.

Refresh-token exchange and blacklist-backed revocation are intentionally not implemented yet. `logout` records an audit event and lets the CLI discard local tokens.

`whoami` returns `current_tenant` as the canonical tenant field and also includes `tenant_id` as a compatibility alias for the current CLI output code.

## User Model Decision

The project already used Django's default auth tables before this module was added. To avoid breaking existing migration history, this module keeps Django's default `User` as the authentication model and stores Nexus-specific account fields in `AccountProfile`.

`AccountProfile` carries:

- `tenant_id`
- `project_id`
- `display_name`
- `phone`
- `company`
- `status`
- `last_login_at`

Future deployments that require a fully custom `AUTH_USER_MODEL` should make that change before the first production migration.

## Tenant Isolation

Account-owned tables added by this module include tenant context fields:

- `AccountProfile.tenant_id`
- `AccountProfile.project_id`
- `PasswordResetToken.tenant_id`
- `PasswordResetToken.project_id`
- `AuditLog.tenant_id`
- `AuditLog.project_id`

The default Django auth tables remain global identity tables. Tenant-scoped authorization is not implemented in this module.

## Write Audit

All write endpoints in this module create `AuditLog` rows:

- successful login: `accounts.login`
- logout: `accounts.logout`
- account update: `accounts.profile.update`
- password reset request: `accounts.password_reset.request`

Failed login attempts are not persisted yet.

## Secret Handling

The API never returns passwords, stored token hashes, upstream provider keys, or API keys.

Password reset creates a one-hour reset token and stores only its SHA-256 hash. Because reset tokens are secrets, the API returns `reset_token_id` and `expires_at`, not the raw reset token. Email delivery can be added later around the generated raw token.

## Mutable Account Fields

`PATCH /api/v1/account/me/` only accepts:

- `display_name`
- `phone`
- `company`

Email, username, status, tenant id, project id, and password are not mutable through this endpoint.
