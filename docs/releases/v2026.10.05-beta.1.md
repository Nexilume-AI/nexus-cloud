# Nexus Cloud v2026.10.05-beta.1

Nexus Cloud is a self-hosted workspace for running Agents, routing model requests,
managing Data Assets, and connecting authorized devices.

This is the first tagged **Beta source release** of the existing public repository.
It includes Cloud Server and Web Console. It is not a first implementation of these
features, a production-readiness certification, or a release of the separate SDK,
Android app, or OpenWrt firmware.

## Start here

- [Try Nexus Cloud online](https://cloud.nexilume.com/)
- [Quick start](../../README.md#quick-start)
- [Docker Compose deployment](../../deploy/community/README.md)
- [Python Agent example](../../examples/readme_launch_agent.py)

To build this exact release:

```sh
git clone --branch v2026.10.05-beta.1 https://github.com/Nexilume-AI/nexus-cloud.git
cd nexus-cloud
docker compose -f deploy/community/compose.yaml up -d --build --wait
```

Open http://127.0.0.1:18090 and follow the README to retrieve the generated initial
password. Requires Git, Docker with Linux containers and Compose v2; x86_64 with
at least 4 GiB available memory is the recommended starting point.

## Included workflows

- Connect model Providers and expose Execution or Aggregation Router endpoints.
- Manage Agent deployments and use Private Display for conversations, plans,
  inline questions and files.
- Manage Data Assets and connect separately installed Computer, Mobile and
  OpenWrt runtimes with explicit authorization.

This repository runs as a single-owner installation. Hosted-service screenshots
may show additional Enterprise menus. Device clients and execution controllers
need their own documented setup; starting Cloud does not deploy them automatically.

## Fixes in this release update

- Model discovery, model health probes and gateway requests now identify
  themselves as `Nexus/1.0`. This avoids upstream rejection of Python's default
  request identifier while preserving authentication and explicit custom
  gateway User-Agent headers.
- A model catalog HTTP 403 is reported as an upstream access-policy rejection,
  not automatically as an expired login or invalid API key.
- Aligned two public recovery-test fixtures with the existing managed-storage
  and degraded-model recovery behavior.
- Corrected historical release-note licensing and deployment guidance.

No database migration, device protocol change or credential rotation is required
by these Provider fixes. TLS, hostname verification, endpoint restrictions and
bounded retry rules remain in place; inference POSTs are not automatically replayed.

## Before exposing a deployment

Configure HTTPS/WSS and follow the deployment guide. Back up the database,
installation configuration, encryption keys and file storage before upgrading.
The documented migration procedure is required for existing installations;
the first-start Compose command is not an automatic upgrade guarantee.

Agent/Provider execution requires configured controllers and applicable image,
network and storage policies. Private deployment addresses, personal credentials, local
research artifacts and the private Enterprise implementation are not distributed.
